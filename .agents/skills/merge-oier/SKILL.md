# 合并选手条目

帮用户合并 `data/raw.txt` 里被错误拆成多条记录的选手。文件很大（约 29 万行），搜索一律用 `grep`/`awk`，不要整读文件。

**修改范围：只允许修改 `data/raw.txt` 目标行的第 9 列（标识符）。** 前 8 列（比赛名、奖项、姓名、年级、学校、分数、省份、性别）只可用于定位和判断，必须逐字节保留，即使发现错误也不能顺手纠正。保留分隔符、换行和行序，不增删记录，不修改其他文件。

如果目标记录姓名不同，或仅改标识符无法得到期望分组，就说明原因并停止，不能通过修改其他字段来实现合并。

## 数据格式

每个非注释、非空的行恰好有 9 个逗号分隔的字段

```
比赛名,奖项,姓名,年级,学校,分数,省份,性别,标识符
```

- 以 `#` 开头的行是注释。
- 性别和标识符可以是空串。
- 标识符用来区分同名的不同选手，是关键字段。

## 标识符与合并的原理

生成器用 `(姓名, 标识符)` 对记录做初步分组。

- 没有标识符的条目走 `Record.distance()` 自动合并（阈值 240），它考察学校、省份、年级、性别和比赛时间线的一致性。
- 有标识符的选手被锁定，自动合并既不会拆开他，也不会把他并给别人。所有 `(姓名, 标识符)` 相同的条目是一个人。

旧标识符可能正是同一个人被拆开的原因。清空后，旧记录可以和已有的空标识符记录一起参加自动合并，之后新增的空标识符记录也有机会并入。形如 `<initials>` 的部分还用于指定姓名首字母，评估清空方案时应核对是否需要保留这个读音设置。

## 从链接查姓名

用户给的链接形如 `https://oier.baoshuo.dev/oier/124550`，其中的数字是有效行号，从 1 开始计数，只数非注释、非空的行。查姓名用

```bash
awk 'BEGIN{n=0} /^[^#]/{n++; if(n==TARGET_ID){print NR": "$0; exit}}' data/raw.txt
```

从那一行取出第 3 个字段（姓名）。链接只定位一条记录，当前页面包含的全部记录要从模拟分组中核对。如果该有效行号已不是当前某组的 UID，以用户给出的比赛、学校等描述核对目标。

## 预备步骤 获取 issue 上下文（如有）

用户给了 GitHub issue 编号（比如说 "merge #123" 或提到某个 issue），先取来看。

```bash
gh issue view <number> --comments
```

结合 issue 正文及相关补充，保留用户最新明确指定的合并范围和例外。

## 工作流程

### 第 1 步 确定这个人

逐条落实用户描述的比赛、年份、学校、年级、转学经历和同名例外，把「哪几条合到哪个人」对应到具体记录。链接和姓名用来找候选，用户给出的归属和排除条件决定哪些记录进入方案。

给了链接就按上面的办法解析出姓名。只给了姓名就直接搜

```bash
grep -n '姓名' data/raw.txt
```

要精确匹配姓名列，避免校名等字段带来的误匹配，用

```bash
awk -F',' '!/^#/ && $3=="姓名" {print NR": "$0}' data/raw.txt
```

### 第 2 步 找出全部条目并评估

用生成器确认当前分组。对照用户描述与比赛、学校和年级时间线，列出目标行、已有标识符以及要单独保留的同名记录。若描述与数据冲突，而且会影响条目归属，指出对应的记录并询问这一处。

```bash
generator/.venv/bin/python generator/tools/oier_check.py simulate '<姓名>'
```

### 第 3 步 分析并提出合并方案

用该姓名的全部记录写出期望分组，每人一组，组内用逗号分隔物理行号，组间用 `|` 分隔。无关同名选手按当前分组列入。当前分组已符合期望时，直接说明结果。

优先模拟只清空待合并记录中已有的标识符，其他行保留原值。下面的例子假设要把物理行 12、34、56 并成一人，其中 12 和 34 有标识符，78、90 属于另一位选手。

```bash
generator/.venv/bin/python generator/tools/oier_check.py simulate '<姓名>' --assign '12=,34=' --expect '12,34,56|78,90'
```

- 校验得到完整的期望分组且清空符合已知的读音要求时，优先建议删除这些标识符。列出要清空的第 9 列原值，并说明自动合并如何处理这些记录。
- 清空后目标记录仍被拆开、误并了同名选手，或需要保留读音设置时，再尝试让目标行共用一个标识符。优先沿用目标行已有且未被其他人使用的值，需要新值时沿用命名习惯，再用 `--assign` 和完整的 `--expect` 校验。
- `--strip` 会模拟清空该姓名下的全部标识符。用它诊断时，仍须用 `--assign` 验证实际准备修改的那些行。只提出通过模拟且符合用户指定范围的方案。

### 第 4 步 展示结果并确认写入范围

请求确认之前，先按人分组输出找到的条目详情。每组给出

1. 按比赛年份排序的全部条目，每行显示比赛、奖项、年级、学校、省份、分数和已有标识符。
2. 年级变化，即各条目年级组成的序列，用 `→` 分隔。示例 `年级：小学/无 → 五年级 → 六年级 → 初一 → 初二 → 初三 → 高一 → 高二`
3. 学校变化，即学校组成的序列，连续相同的学校只保留一个。示例 `学校：燕山小学 → 长沙市燕山小学 → 长沙市湘郡培粹实验中学 → 长沙市长郡中学`

展示合并方案，内容包括

- 用户描述的哪些记录会合并，以及模拟校验得到的分组。
- 要修改的物理行及其当前值和计划值，清空时写明「标识符留空，保留行末逗号」。

用户只要建议时，到此结束。用户无明确要求，或者要求修改但还未明确授权拟议的改法时，使用 `AskUserQuestion` 展示方案后请其确认。

### 第 5 步 执行合并

**注意。** `Edit` 工具要求在会话中至少用 `Read` 读过该文件一次才能编辑。raw.txt 太大不能整读，用 `Read` 的 `offset` 和 `limit` 只读目标行附近（比如 `offset=行号-1, limit=3`），既满足前置条件，又不加载整个文件。

写入前记录目标行原文和工作区已有差异，供改后复核。按确认的物理行号逐行修改，只替换最后一个逗号之后、换行符之前的标识符值。例如清空时把 `男,A` 改为 `男,`。整行替换时，直接保留原行到最后一个逗号（含逗号）的全部内容。若使用 `Edit`，`old_string` 必须唯一，必要时加入原样保留的上下文。

### 第 6 步 复核与提交

对照本次操作前的内容检查差异（工作区原本无改动时可用 `git diff -- data/raw.txt`）：每处改动都应对应已确认的物理行，修改前后都恰好有 9 列，且到最后一个逗号为止的内容与换行完全一致；只有第 9 列变成计划值。发现越界改动就先撤回本次越界改动，保留用户已有改动，复核通过后才能提交。

重新运行 `oier_check.py simulate '<姓名>'`，对照期望分组检查写入后的实际结果。

全部编辑完成后用 `AskUserQuestion` 问用户是否提交。默认提交标题按这个格式

```
data: fix {姓名} ({省份列表，用半角逗号分隔})
```

比如合并王泽宇在江苏和上海的条目，默认标题是 `data: fix 王泽宇 (江苏,上海)`。

预备步骤里拿到过 issue 编号的话，在提交信息正文末尾加一行

```
Resolves {owner}/{repo}#{issue_number}.
```

然后用确认过的标题和信息创建提交。

## 重要规则

- 不带 grep/awk 过滤不要读 raw.txt，文件太大。
- 搜索时优先用 `awk -F',' '$3=="姓名"'` 精确匹配姓名列，避免校名等字段含这个名字造成误报。
- 用户给的信息互相矛盾时问清楚，不要猜。
- 标识符可以是任意字符串，不限于单个字母。看看该姓名下已有的标识符，沿用它既有的命名模式。
