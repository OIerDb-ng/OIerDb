# 合并选手条目

帮用户合并 `data/raw.txt` 里被错误拆成多条记录的选手。文件很大（约 29 万行），搜索一律用 `grep`/`awk`，不要整读文件。

## 数据格式

每个非注释、非空的行恰好有 9 个逗号分隔的字段

```
比赛名,奖项,姓名,年级,学校,分数,省份,性别,标识符
```

- 以 `#` 开头的行是注释。
- 性别和标识符可以是空串。
- 标识符用来区分同名的不同选手，是关键字段。

## 标识符与合并的原理

代码（`oier.py`、`main.py`）用 `(姓名, 标识符)` 作键来识别一个选手。键相同的条目永远算同一个人。

- 没有标识符的条目走 `Record.distance()` 自动合并（阈值 240），它考察学校、省份、年级、性别和比赛时间线的一致性。
- 有标识符的选手被锁定，自动合并既不会拆开他，也不会把他并给别人。所有 `(姓名, 标识符)` 相同的条目是一个人。

所以要强制合并被错误拆开的条目，就给它们同一个标识符。要阻止合并，就给不同的标识符。没有标识符不等于条目被拆错了，自动合并可能已经处理正确。用户既然要求合并，说明这一例自动合并没做好。

## 从链接查姓名

用户给的链接形如 `https://oier.baoshuo.dev/oier/124550`，其中的数字是有效行号，从 1 开始计数，只数非注释、非空的行。查姓名用

```bash
awk 'BEGIN{n=0} /^[^#]/{n++; if(n==TARGET_ID){print NR": "$0; exit}}' data/raw.txt
```

从那一行取出第 3 个字段（姓名）。**先输出姓名**，让用户在改动之前确认。

## 预备步骤 获取 issue 上下文（如有）

用户给了 GitHub issue 编号（比如说 "merge #123" 或提到某个 issue），先取来看。

```bash
gh issue view <number>
```

从 issue 正文提取姓名、链接、省份、学校和合并要求，和用户直接给的信息一起用。带着全部信息进入第 1 步。

## 工作流程

### 第 1 步 确定这个人

从用户输入提取姓名、链接、比赛名、省份、学校、年级等信息，用来定位候选条目。

给了链接就按上面的办法解析出姓名。只给了姓名就直接搜

```bash
grep -n '姓名' data/raw.txt
```

要精确匹配姓名列，避免校名等字段带来的误匹配，用

```bash
awk -F',' '!/^#/ && $3=="姓名" {print NR": "$0}' data/raw.txt
```

### 第 2 步 找出全部条目并评估

过一遍所有匹配行，结合用户给的背景（省份、学校、比赛时间线）按人分组，弄清

- 哪些条目属于用户要合并的那个人。
- 是否存在同名但属于别人的条目。
- 哪些条目已经有标识符。

### 第 3 步 分析并提出合并方案

**情形 A，该姓名没有其他条目，所有条目属于同一个人。** 给所有条目分配同一个标识符，惯用 `A`。这是最简单的情况。

**情形 B，存在其他条目，多个人同名。** 列出全部条目并按人分组，确定哪些条目应该合在一起。已有标识符的条目保持不变，没有标识符的按已有命名习惯或 A、B、C、D 的字母顺序分配新标识符。把完整方案摆出来，写明每个人分到的标识符。

### 第 4 步 展示结果并与用户确认

请求确认之前，先按人分组输出找到的条目详情。每组给出

1. 按比赛年份排序的全部条目，每行显示比赛、奖项、年级、学校、省份、分数和已有标识符。
2. 年级变化，即各条目年级组成的序列，用 `→` 分隔。示例 `年级：小学/无 → 五年级 → 六年级 → 初一 → 初二 → 初三 → 高一 → 高二`
3. 学校变化，即学校组成的序列，连续相同的学校只保留一个。示例 `学校：燕山小学 → 长沙市燕山小学 → 长沙市湘郡培粹实验中学 → 长沙市长郡中学`

展示完摘要后用 `AskUserQuestion` 提出合并方案，请用户确认，内容包括

- 要合并的是哪个人的条目。
- 会分配哪些标识符，分别给哪些行。
- 存疑的情况。

有不清楚的地方就问。没有用户明确同意不要动手。

### 第 5 步 执行合并

**注意。** `Edit` 工具要求在会话中至少用 `Read` 读过该文件一次才能编辑。raw.txt 太大不能整读，用 `Read` 的 `offset` 和 `limit` 只读目标行附近（比如 `offset=行号-1, limit=3`），既满足前置条件，又不加载整个文件。

然后用 `Edit` 逐行更新标识符字段。标识符是第 9 个也是最后一个字段，后面不要再加逗号。常见替换有

- 性别为空、标识符为空（行尾是 `,,`），把结尾的 `,` 换成 `,标识符`，行尾不再留逗号。
- 性别非空、标识符为空（行尾是 `男,`），换成 `男,标识符`。
- 已有标识符要改的，直接把旧标识符替换成新的。

还要记住

- 不要改变行之间的相对顺序，只改行内字段。
- 其他字段原样保留。
- `old_string` 在文件里必须唯一，必要时带上足够长的上下文，比如整行内容，或者姓名加学校加比赛拼出的足够长子串。
- 要编辑多行时，可以一次 `Read` 覆盖所有目标行的小范围，再逐行编辑。

### 第 6 步 提交

全部编辑完成后用 `AskUserQuestion` 问用户是否提交。默认提交标题按这个格式

```
data: fix {姓名} ({省份列表，用半角逗号分隔})
```

比如合并王泽宇在江苏和上海的条目，默认标题是 `data: fix 王泽宇 (江苏,上海)`。

预备步骤里拿到过 issue 编号的话，在提交信息正文末尾加一行

```
Resolves {owner}/{repo}#{issue_number}.
```

然后用确认过的标题和信息创建提交。

## 重要规则

- 不带 grep/awk 过滤不要读 raw.txt，文件太大。
- 改动前先和用户确认姓名。
- 执行合并前必须获得用户同意。
- 搜索时优先用 `awk -F',' '$3=="姓名"'` 精确匹配姓名列，避免校名等字段含这个名字造成误报。
- 用户给的信息互相矛盾时问清楚，不要猜。
- 标识符可以是任意字符串，不限于单个字母。看看该姓名下已有的标识符，沿用它既有的命名模式。
