# 拆分选手条目

帮用户拆开 `data/raw.txt` 里被错误并成一条的选手记录。文件很大（约 29 万行），搜索一律用 `grep`/`awk`，不要整读文件。

## 数据格式

每个非注释、非空的行恰好有 9 个逗号分隔的字段

```
比赛名,奖项,姓名,年级,学校,分数,省份,性别,标识符
```

- 以 `#` 开头的行是注释。
- 性别和标识符可以是空串。
- 标识符用来区分同名的不同选手，是关键字段。

## 标识符与拆分的原理

代码（`oier.py`、`main.py`）用 `(姓名, 标识符)` 作键来识别一个选手，生成时分两步：

- **有标识符的记录被锁定。** 键相同的记录永远是同一个人，自动合并既不会拆开他们，也不会把他们并给别人。
- **空标识符的记录进入该姓名的自动合并池。** `Record.distance()`（阈值 240）考察学校、省份、年级、性别和比赛时间线，把池子聚类成若干人。

所以"一个条目混了多个人"只有两种成因，修复方式不同：

1. **历史上被加了同一个（错误的）标识符**，把不同的人锁成了一个人。修法是移除或改写这些标识符，让记录回到自动合并池。多数案例属于这种（比如把相隔十几年的同名记录用 `A` 锁在了一起）。
2. **自动合并本身把距离过近的不同人并成了一人。** 这才需要给其中一部分记录新增不同的标识符来强制分开。

## 为什么不能随手加标识符（未毕业规则）

新比赛的获奖记录录入时（见 add-contest 技能）**一律以空标识符追加**，只会落进自动合并池。给一个人加了标识符等于把他"锁死"：他未来新公布的获奖记录再也无法并入他，只能错并给同名的别人，或者凭空多出一个新条目。因此**空标识符必须留给最可能继续参赛的人**。

判断"还会不会参赛"看高中毕业时间：初中入学年份 em，高中毕业在 em+6 年 6 月。检查工具会按生成器同样的口径自动估算并在输出里标注"已毕业/未毕业"。据此遵守以下规则：

1. **能不加就不加。** 对尚未高中毕业的人，如果不加标识符、自动合并就能把他正确地合并成一个人（或者把错误记录从他身上剥离出去），就不要给他加标识符——通常这意味着只需移除错误的旧标识符，不新增任何东西。
2. **必须加时挑人。** 需要标识符才能分开几个人时，已毕业的人优先拿标识符；如果涉及的人都没有毕业，给"最近一次参赛记录最久远"的那个人加标识符，空标识符留给最近记录最新的人。若某人自己的记录必须靠标识符才能聚成一人（去掉后会被拆散），他拿标识符是不得已，不适用第 1 条。

## 检查工具 `oier_check.py`

`generator/tools/oier_check.py` 用生成器本身的逻辑（`Record.distance`、阈值 240）模拟某个姓名会被合并成哪几个人，并给出符合上述规则的标识符建议。在仓库任意目录都能运行：

```bash
generator/.venv/bin/python generator/tools/oier_check.py lines <姓名>
generator/.venv/bin/python generator/tools/oier_check.py simulate <姓名> [选项]
```

- `lines` 列出该姓名所有行的物理行号（`grep -n` 看到的）、有效行号（网站链接里的 uid）和原始内容。
- `simulate` 按当前状态模拟分组，每人给出记录时间线、年级/学校序列、毕业估算和最近参赛。
- `--strip` 假设去掉该姓名全部标识符后模拟——用于判断成因和"不加标识符能否修好"。
- `--assign 行号=标识符,...` 假设某些行的标识符被改成指定值（空串表示移除）后模拟。
- `--expect '行号,行号|行号,...'` 给出按人分组的期望结果后，工具会：对比当前状态、对比去标识符状态；若去掉标识符即可达标，直接建议"全部移除、不要新增"；否则给出最小的标识符修改建议（标注每组的毕业状态与最近参赛、谁保留空标识符），并按建议模拟校验。已给出 `--expect` 时再给 `--strip` 或 `--assign` 就是只校验该假设。
- 行号一律用物理行号。退出码 0 表示校验通过（或未校验），1 表示不一致或出错；建议的模拟若校验失败（✗），用 `--assign` 手工迭代调整。

## 从链接查姓名

用户给的链接形如 `https://oier.baoshuo.dev/oier/124550`，其中的数字是有效行号，从 1 开始计数，只数非注释、非空的行。查行用

```bash
awk 'BEGIN{n=0} /^[^#]/{n++; if(n==TARGET_ID){print NR": "$0; exit}}' data/raw.txt
```

从那一行取出第 3 个字段（姓名）。**先输出姓名**，让用户在改动之前确认。

## 预备步骤 获取 issue 上下文（如有）

用户给了 GitHub issue 编号（比如说 "split #123" 或提到某个 issue），先取来看。

```bash
gh issue view <number>
```

从 issue 正文提取姓名、链接、省份、学校和拆分要求，和用户直接给的信息一起用。

## 工作流程

### 第 1 步 确定这个人

同 merge-oier：给了链接按上面的办法解析出姓名；只给了姓名就用 `awk -F',' '!/^#/ && $3=="姓名" {print NR": "$0}' data/raw.txt` 精确匹配姓名列。然后跑 `oier_check.py lines <姓名>` 拿到全部行。

### 第 2 步 找出全部条目并按真实身份分组

过一遍所有行，结合用户和 issue 给的背景（学校、省份、年级时间线、性别）把行分组到真实的"人"。弄清

- 哪些行属于谁；同名但无关的行保持不动。
- 哪些行已经有标识符，当前是怎么锁的。
- 每个人是否已高中毕业、最近一次参赛是哪年（跑 `simulate` 即可看到）。

用户信息互相矛盾、证据不足以分组时，问清楚，不要猜。

### 第 3 步 用工具验证分组并确定方案

把第 2 步的分组写进 `--expect`（每人一组，行号用物理行号、逗号分隔、竖线分组），跑

```bash
generator/.venv/bin/python generator/tools/oier_check.py simulate <姓名> --expect '<分组>'
```

- 输出"去掉全部标识符后自动合并即可得到期望分组"→ **路径一**：只移除现有错误标识符，不新增。
- 输出建议列表 → **路径二**：按建议调整标识符（建议已遵守未毕业规则，但要自己复核一遍毕业估算是否合理，估算基于年级推算，个别记录年级缺失时会偏）。
- 校验为 ✗ → 用 `--assign` 手工调整假设再试，直到某个假设通过；那个假设就是方案。

### 第 4 步 展示结果并与用户确认

按人分组输出（同 merge-oier 的展示）：每人的全部条目（按年份排序，显示比赛、奖项、年级、学校、省份、分数、行号、当前标识符→目标标识符）、年级序列、学校序列、毕业状态与最近参赛。然后用 `AskUserQuestion` 提出方案，写明每个人分到的标识符（或保持空）以及为什么空标识符留给那个人。没有用户明确同意不要动手。

### 第 5 步 执行修改

**注意。** `Edit` 工具要求在会话中至少用 `Read` 读过该文件一次才能编辑。raw.txt 太大不能整读，用 `Read` 的 `offset` 和 `limit` 只读目标行附近（比如 `offset=行号-1, limit=3`）。

然后用 `Edit` 逐行更新第 9 个（最后一个）标识符字段，常见替换有

- 空 → 标识符：行尾的 `,` 换成 `,标识符`，行尾不再留逗号。
- 标识符 → 空：行尾的 `,标识符` 换成 `,`。
- 标识符 → 标识符：直接替换。

还要记住

- 不要改变行之间的相对顺序，只改行内标识符字段，其他字段原样保留。
- `old_string` 在文件里必须唯一，必要时带整行或足够长的上下文。
- 目标行多时，可以一次 `Read` 覆盖所有目标行的小范围，再逐行编辑。

### 第 6 步 复核与提交

改完重跑 `oier_check.py simulate <姓名>`，确认当前状态的模拟分组与期望一致（每人自成一人、未毕业者按规则持有空标识符）。然后按 merge-oier 的约定提交：用 `AskUserQuestion` 问用户是否提交，默认标题

```
data: fix {姓名} ({省份列表，用半角逗号分隔})
```

有 issue 编号的话在提交信息正文末尾加 `Resolves {owner}/{repo}#{issue_number}.`。

## 重要规则

- 不带 grep/awk 过滤不要读 raw.txt，文件太大。
- 改动前先和用户确认姓名；执行拆分前必须获得用户同意。
- 搜索时用 `awk -F',' '$3=="姓名"'` 精确匹配姓名列，避免校名等字段造成误报。
- 拆分不等于加标识符：优先移除错误标识符交给自动合并，只在自动合并分不开时才新增（见"未毕业规则"）。
- 新增标识符时沿用该姓名已有的命名模式（A、B、C……），不要与该姓名仍在使用的其他标识符冲突。
- 混进条目的行若属于另一个**已有**同名条目，只需把它并到对的人那里（改标识符即可），不要动别的字段。
