## 一、为什么需要另一个模型

旧模型是一个**无上限的累加式**：

```
score(人) = Σ 1.25^(year-2000) · rank_coefficient · contest_type_coefficient
```

用线上 125,964 人的榜单复刻验证后，发现四个效度问题：

| 现象 | 实测 |
|---|---|
| 同一人、同一年，NOI 金牌比 IOI 金牌多 65% | 12/12 全部成立，中位 1.65 倍（`tc` 1.0 vs 0.6，`rc` 几乎相同） |
| IOI 金牌得主并不在榜首 | 中位 #1,112、最差 #22,372；最差者被 **17,928** 个无全国奖牌的人超过 |
| 历史成绩被复利清零 | 5 位 IOI 金牌得主总分低于**一个** 2025 年 NOIP 省一（1,436.8 vs 2,342.6 等） |
| 参与次数本身就是分数 | 记录条数与中位排名单调：1 条 #89,266 → 10 条 #2,524 → 20 条 #110 |

## 二、新模型

排序键（严格字典序）：

```
(最高赛事层级, 该层级上的最高奖项, 其余成绩分, uid)
```

1. **参加过高等级赛事的优先** → 第一位是最高赛事层级。
2. **在高等级赛事获得过高等级奖项的优先** → 第二位是**该层级上**的最高奖项。
3. **两者都相同时再看其他赛事成绩** → 第三位是 `secondary`，取值 `[0, 1)`。
4. **再相同按 uid**（= 首次有效行号），保证结果稳定可复现。

注意第 2 条是「该层级上」而不是「全局最高奖项」：IOI 铜牌 + NOI 金牌的选手，
主键是 `(IOI, 铜牌)`，NOI 金牌只进入 `secondary` —— 这是「先看最高舞台」的直接推论。

### 规则表 `data/ranking.json`

```jsonc
"contest_tier": {          // 越大越高
  "IOI": 9,
  "NOI": 8, "CTSC": 8, "APIO": 8,   // 同一档：参赛池重叠，CTSC/APIO 均以 NOI 成绩为资格
  "WC": 7, "NOID类": 6,
  "NGOI": 5, "NOIST": 5, "WC-AI": 5,
  "NOIP": 2,                // 仅作 2020 年前的兜底，实际由年份规则覆盖
  "NOIP提高": 2, "CSP提高": 2,   // 省赛提高级：同一档
  "NOIP普及": 1, "CSP入门": 1    // 省赛入门级：同一档
},
"noip_unsplit_since": 2020,
"noip_unsplit_tier": 3,     // 2020 年起 NOIP 不再分普及/提高，单组别，高于 CSP-S
```

层级判定是 **按 (赛事类型, 年份)** 的，不是纯类型表：

- `NOIP` 且年份 ≥ 2020 → 层级 3（高于 CSP-S）。数据里 `NOIP` 恰好只有 2020–2025 六场。
- `NOIP 提高组`（2008–2018）与 `CSP-S`（2019 起）→ 同为层级 2。
- `NOIP 普及组` 与 `CSP-J` → 同为层级 1。

这样处理的原因是它们是**同一赛事在不同年代的形态**，而不是难度不同的两个比赛：

- 2019 年前：`NOIP 提高组 / 普及组`
- 2020 年起：NOIP 恢复为**单组别**省级联赛，CSP-S/J 同时保留（CSP-S 第一轮承担资格赛功能）

若按类型给固定层级，会出现「2021 年 NOIP 三等奖 < 2021 年 CSP-S 一等奖」这类跨年代错位。

`NOI / CTSC / APIO` 同档：同一批人的不同赛场。若把 APIO 放在 NOI 下一层，
会出现「APIO 国际金牌排在 NOI 铜牌之后」——实测初版就发生了（#3827 vs #2399）。

```jsonc
"award_rank": {            // 只在同一赛事层级内部比较
  "国际金牌": 5, "金牌": 5, "国际银牌": 4, "银牌": 4,
  "国际铜牌": 3, "铜牌": 3, "一等奖": 3, "前5%": 3,
  "二等奖": 2, "前15%": 2, "三等奖": 1, "前25%": 1
}
```

APIO 的「国际金牌」与 NOI 的「金牌」同档（5）：两者都是各自赛场的第一档，
同一档内由 `secondary` 区分。

### `secondary`（其余成绩）

- 每个 `(赛种, 年份)` 只取**最好一条**，避免同一场比赛的多个组别重复计分。
- 基础分 = `rank_coefficient / 100 ∈ [0,1]`（场内百分位，不掺赛种规模）。
- 乘以 `tier_floor + (1 - tier_floor) · tier / 9`：其余成绩里更高层级的赛事更重。
- **默认不做时间衰减**（`decay_per_year = 0`）。主键已经决定了「哪个舞台」，
  桶内再按年代加权会重新引入「越近越优先」。需要时可以打开，线性衰减、有下限，不用复利。
- 按分数降序施加 `1, 0.5, 0.25, …` 的权重，使「堆次数」的边际收益迅速消失。
- 最后映射到 `[0,1)`，保证主键永远优先于其余成绩。

### 展示用评分

```
rating = 主键高位 × 1000 + 主键低位 × 100 + 99 × secondary
```

它是严格单调的：`tier` 差 1 级 = 1000 分，奖项差 1 档 = 100 分，其余成绩 < 100 分。
`dist/result.txt` 的分数列写的就是它（旧模型该列是原始累加分数）。

### NGOI 的同卷处理

`NGOI` 不是额外竞赛，而是「当年 NOIP 成绩在全体女选手中的排名」：`NGOI(y)` 就是 `NOIP(y-1)`
的分数在女选手中的名次。判定见 `generator/audit_ngoi.py` / `audit_merge.py`：把每条 NGOI
与**同一人、上一学年**的 NOIP 原始分数逐条比对。

对齐必须用 `school_year`，不能用 `contest.year`：数据里 NGOI 的年份编码前后不一致
（NGOI2022 存 `year=2022, fall=False`；NGOI2024 存 `year=2023, fall=True`），
只有 `school_year` 能把它们统一到同一个 NOIP 学年。

| NGOI | 对应 NOIP | 可比记录 | 分数完全一致 | 结论 |
|---|---|---:|---:|---|
| NGOI2022 | NOIP2021 | 21 | 0（0%） | 独立赛事，保留 |
| NGOI2023 | NOIP2022 | 34 | 0（0%） | 独立赛事，保留 |
| **NGOI2024** | NOIP2023 | 265 | **265（100%）** | **同卷，按选手处理** |
| **NGOI2025** | NOIP2024 | 260 | **260（100%）** | **同卷，按选手处理** |
| **NGOI2026** | NOIP2025 | 255 | **255（100%）** | **同卷，按选手处理** |

判定在生成时自动完成（`ranking.detect_derived_contests()`）。同卷年份的 NGOI 记录若有
同学年 NOIP 记录，则不参与 `best_of`（最高赛事/奖项）和 `secondary`；若没有对应 NOIP，
则不参与主键，而是用该 NGOI 原始分在同学年、同省份的 NOIP 记录中对应的最高奖项等级，
计入相当于 NOIP 的 `secondary` 加分。这样既避免同一成绩重复计分，也能让只有 NGOI 记录的
选手按照其原始分在本省 NOIP 中对应的奖项等级获得合理的排名信息。

> 注：按姓名而非合并后的 uid 统计时，2025/2026 会出现 1～3 条「不一致」——那是同名不同人
> 被误当成同一人；用合并后的 uid 复核，三年都是 100%。

## 三、用法

```bash
cd generator
python main.py --lex-rank        # 等价于 --rank=lex
```

产出：

| 文件 | 内容 |
|---|---|
| `dist/result.txt` | 新排名的榜单（与原格式完全一致，9 字段） |
| `dist/result_old.txt` | 旧模型的榜单，用于 A/B 对比 |
| `dist/rank_diff.tsv` | 全员对照：新旧名次、变动、最高成就、其余成绩、旧分、记录数 |
| `dist/rank_preview.md` | 人类可读报告：前 100、IOI 金牌对照、变动最大的人、效度检查 |

不加参数时行为完全不变。

### 本地预览页

```bash
python build_preview.py     # 生成 dist/preview.html + dist/preview_data.js
```

`dist/preview.html` 可以直接双击打开（数据在旁边的 `preview_data.js` 里，不依赖服务器）。
页面支持：姓名 / 拼音首字母 / 赛事名搜索、按层级筛选、新旧模型切换排序、点击查看全部记录，
以及 NGOI 派生赛事的判定表。

### 原前端（apps/frontend-legacy）

在仓库根目录双击 `start-local.cmd` 即可（`start-local.cmd --regen` 会强制重算数据）。
脚本做四件事：检查依赖 →（必要时）跑生成器 → 把 `dist/` 铺成前端可读的
`public/data/static.<sha7>.json` 与 `result.<sha7>.txt` 并写 `.env.local` → 启动 Vite，

## 四、已知取舍

1. **严格字典序的代价**：一枚 IOI 铜牌会排在所有 NOI 金牌之前。这是「参加过高等级赛事优先」
   的字面执行结果。若希望反过来，把 `ranking.json` 的
   `"primary_order": ["award", "tier"]` 即可（同一人同年 NOI 金/IOI 金 的倒挂会重新出现）。
2. **层级是粗粒度的**：同一层级内只靠奖项和其余成绩区分，名次（rank）本身不直接参与主键。
   这保证了「同层同奖」的人可公平比较，但会让「同奖不同名次」的差异只体现在 `secondary` 里。
3. **`secondary` 不分年份**：同一个人的 10 条成绩按 1, 1/2, 1/4… 加权，靠的是成绩质量而不是时间。
4. **学校榜同步使用 LexRank**：学校内的学生按个人 LexRank 排序，最高学生的评分作为主值，
   其余学生按 `1/2, 1/4, ...` 衰减后聚合；同一学生在学校的多条比赛记录只计一次。
   因此学校榜优先体现最高成就，同时把学校整体的学生梯队作为同档内补充。

## 五、校验

`generator/rank_check.py` 会检查四条不变量：

1. `rating` 单调不增；
2. `(层级, 奖项)` 成段、不交错；
3 . 高层级的最后一名名次 < 下一层级的第一名名次；
4. 同一桶内 `secondary` 单调不增。
